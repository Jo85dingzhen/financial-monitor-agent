# Codex 本地无法使用的常见原因与排查清单

> 适用于“本地运行 Codex 或 Codex CLI 不工作/报错/无法连接”等情况。

## 1) 安装与版本问题
- **未正确安装或版本不匹配**：确认已安装正确的 Codex 客户端/CLI，并与文档要求的版本一致。
- **PATH 未包含可执行文件**：终端找不到命令会导致“command not found”。

## 2) 认证与密钥配置
- **API Key 或 Token 缺失/无效**：常见表现为 401/403 或提示未授权。
- **环境变量未加载**：比如 `.env` 未被读取、shell 启动脚本未加载导致变量缺失。

## 3) 网络与代理问题
- **公司/学校代理或防火墙**：可能阻止与 API 的连接，出现超时或 DNS 错误。
- **本地 DNS/证书问题**：HTTPS 请求失败可能与证书或 DNS 配置有关。

## 4) 依赖缺失或运行时环境异常
- **Node/Python 版本不符合要求**：CLI 依赖的运行时版本过低/过高都会失败。
- **依赖未安装完整**：比如依赖包安装失败或损坏。

## 5) 配置文件错误
- **配置文件路径错误或格式不合法**：例如 YAML/JSON 语法错误导致加载失败。
- **配置与实际环境不一致**：如地区/端点配置错误导致无法连接。

## 6) 日志与错误信息未收集
- **未查看详细错误输出**：很多问题只能从完整日志中定位。
- **缺少可复现信息**：没有错误堆栈、版本号、执行命令会导致排查困难。

## 7) 基础排查建议（按顺序）
1. 确认安装方式与版本是否符合官方文档。
2. 检查命令是否可被终端找到（PATH）。
3. 确认 API Key/Token 是否正确加载。
4. 关闭/配置代理后重试，或切换网络环境。
5. 查看完整错误日志，记录错误码、堆栈、版本信息。

## 8) 如果仍无法使用，请提供以下信息
- 使用的操作系统与版本
- Codex 客户端/CLI 版本
- 具体命令与完整错误日志
- 认证方式（环境变量/配置文件）
- 是否使用代理或企业网络
