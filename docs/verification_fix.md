# 验证失败问题 - 已修复 ✅

## 🔴 原始问题

运行 `main_v2.py` 后，所有验证都失败：
```
Total Claims: 11
✅ Verified: 0
❌ Failed/Conflict: 11
```

## 🔍 问题根源

**原因**: 采集模块只获取了搜索结果的 snippet（摘要），没有抓取完整的网页内容。

- **原始文章**: 只有 100-200 字的 snippet
- **AI 生成的声明**: 包含详细数据（如 "75.9元"）
- **验证器**: 在 snippet 中找不到这些详细数据 → 验证失败

## ✅ 解决方案

已实现**网页内容抓取功能**，自动获取完整文章正文。

### 新增功能

1. **`fetch_full_text()` 函数** ([gather_demo.py:100-178](gather_demo.py#L100-L178))
   - 智能解析 HTML，提取正文内容
   - 支持多种网站结构（政府网站、新闻媒体）
   - 自动移除导航、广告等无关内容
   - 超时保护（10秒）

2. **自动集成到采集流程**
   - 每篇文章自动抓取完整内容
   - 填充 `full_text` 字段
   - 失败时自动回退到 snippet

3. **配置选项** ([main_v2.py:69](main_v2.py#L69))
   ```python
   CONFIG = {
       "extract_full_text": True,  # 可关闭（不推荐）
       ...
   }
   ```

## 🔧 故障排查

### 问题 1: 抓取失败过多

**症状**:
```
⚠ 全文抓取失败，使用 snippet
```

**解决**:
1. 检查网络连接
2. 增加超时时间（修改 `fetch_full_text(url, timeout=10)` 中的 10）
3. 检查目标网站是否需要特殊处理

### 问题 2: 验证仍然失败

**可能原因**:
1. 网站使用 JavaScript 渲染（需要 Selenium）
2. 网站有反爬虫机制
3. 声明是分析性的（无法从原文验证）

**解决**:
- 查看 `audit_log_*.json` 中的 `supporting_evidence` 字段
- 检查 `full_text` 是否包含相关内容

### 问题 3: 采集速度太慢

**解决**:
```python
CONFIG = {
    "extract_full_text": False,  # 临时关闭
    ...
}
```
